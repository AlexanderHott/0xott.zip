tmux is a *terminal multiplexer*. 
Primarily, it lets you run multiple shells from within a single terminal window, and those shells keep running when you disconnect.
You can reattach later, even from a different SSH connection. 

A tmux server holds *sessions*. Each session has one or more *windows* (like tabs), and each window is split into one or more *panes*. 

## Scripting

A tmux script can recreate your terminal workspace: create a session, split windows into panes, and start commands in each pane.
Let's look at how to control tmux programmatically.

### Basics

tmux has a powerful scripting API. The only downside is that you have to use short flags (e.g. `-s`, `-t`), which can make it harder to read.

```bash
#!/usr/bin/env bash

set -euo pipefail

SESSION=hello-tmux

tmux new-session -d -c "$PWD" -s "$SESSION" -n files

tmux attach-session -t "$SESSION"
```

`tmux new-session` creates a session:

- `-d`: create it without attaching, so the rest of the script keeps running.
- `-c "$PWD"`: the directory the session starts in.
- `-s "$SESSION"`: the session name.
- `-n files`: the name of the first window. Every new session starts with one window.

`tmux attach-session` attaches your terminal to a session:

- `-t "$SESSION"`: the session to attach to.

### Sending keystrokes

You can run commands in a session by using `send-keys`.

```bash
tmux send-keys -t "$SESSION:files" "ls" Enter
```

`-t` is the "target". It tells tmux where to send the keystrokes.

### Splitting windows

You can have multiple panes in a window.

```bash
tmux new-session -d -c "$PWD" -s "$SESSION" -n files
tmux send-keys -t "$SESSION:files" "ls" Enter

tmux split-window -dh -c "$PWD" -t "$SESSION:files"
tmux send-keys -t "$SESSION:files.1" "ls -la" Enter
```

`tmux split-window` creates a new pane by splitting the target pane:

- `-d`: don't switch to the new pane. The original pane stays active, which matters because targeting a window means targeting its active pane. Without `-d`, a second split of `"$SESSION:files"` would split the new pane instead.
- `-h`: put the new pane to the right, side by side. Without it, tmux uses `-v` and puts the new pane below.
- `-c "$PWD"`: the directory the new pane starts in.
- `-t "$SESSION:files"`: the pane to split. We named the first window `files`, so this targets that window's active (and only) pane.
- `-b`: split the new window before the active pane, so above or to the left.

For `tmux send-keys`, we use the `"$SESSION:files.1"` target, because the new pane is at index 1 in the `files` window.

> Note: window and pane numbers start at 0 by default. Many people set `base-index 1` and `pane-base-index 1` so window numbers match the number row on the keyboard. If you do, the `.1` and `.2` targets in these examples point at different panes. Shift them up by one, or use tokens like `{right}`.

For a three-way split, you need to split a pane once, and then split one of the two panes you just created.

```bash
tmux new-session -d -c "$PWD" -s "$SESSION" -n files
tmux send-keys -t "$SESSION:files" "ls" Enter

tmux split-window -dh -c "$PWD" -t "$SESSION:files"
tmux send-keys -t "$SESSION:files.1" "ls -la" Enter

tmux split-window -dh -c "$PWD" -t "$SESSION:files.1"
tmux send-keys -t "$SESSION:files.2" "pwd" Enter
```

In the last `split-window`, we target `"$SESSION:files.1"`, so the pane on the right will be split in half. This makes a 50%-25%-25% split.
You can control the size of the splits directly with the `-l` option, or tell tmux to rearrange the panes with a predefined layout.

For `-l`, you can either specify the number of terminal cells, or the percentage of the available space. For the first split window, if we specified `-l 66%`, we would end up with a roughly even split because the last one would split that 66% in half, resulting in a 33%-33%-33% layout.

tmux has a few predefined layouts that can be set with `tmux select-layout -t "$SESSION:files" <layout>`.

> | Layout                     | Description |
> | -------------------------- | ----------- |
> | `even-horizontal`          | Panes are spread out evenly from left to right across the window. |
> | `even-vertical`            | Panes are spread evenly from top to bottom. |
> | `main-horizontal`          | A large (main) pane is shown at the top of the window and the remaining panes are spread from left to right in the leftover space at the bottom. Use the `main-pane-height` window option to specify the height of the top pane. |
> | `main-horizontal-mirrored` | The same as `main-horizontal` but mirrored so the main pane is at the bottom of the window. |
> | `main-vertical`            | A large (main) pane is shown on the left of the window and the remaining panes are spread from top to bottom in the leftover space on the right. Use the `main-pane-width` window option to specify the width of the left pane. |
> | `main-vertical-mirrored`   | The same as `main-vertical` but mirrored so the main pane is on the right of the window. |
> | `tiled`                    | Panes are spread out as evenly as possible over the window in both rows and columns. |

### New Windows

If you want another window to switch to, create one with `tmux new-window`.


```bash
tmux new-window -c "$PWD" -t "$SESSION" -n another-window
```

### Resuming

Depending on your script, you may want to attach to the session if it already exists instead of creating the panes again.
You can check if the session exists with `tmux has-session`.

```bash
if tmux has-session -t "$SESSION" 2>/dev/null; then
  exec tmux attach-session -t "$SESSION"
fi
```

We use `exec` here to replace the Bash script process with the tmux client.
This prevents the rest of the script from running after you detach.

### Options

tmux has configuration options that change how it behaves.
Some of these are useful in scripts.

You may want the tmux session to be destroyed when you detach.

```bash
tmux set-option -t "$SESSION" destroy-unattached on
```

There are many other options and configuration you can set. See the OPTIONS section of `man tmux`.

## Examples

### tmux sessionizer

Let's say all of your coding projects live in `~/Projects/`. Let's write a script that lists all those projects with fzf, and then opens or attaches to a tmux session in that directory with a window for running your dev server and one for your editor.

```bash
#!/usr/bin/env bash

set -euo pipefail

PROJECTS="${PROJECTS:-$HOME/Projects/}"
```

`PROJECTS` defaults to `~/Projects/`. Set the `PROJECTS` environment variable to change that.

```bash
dir=$(fd --type d --max-depth 1 . "$PROJECTS" |
  fzf --delimiter / --with-nth -2 --preview 'ls -A {}') || exit 0
```

`fd` lists the directories directly inside `$PROJECTS`, and `fzf` lets you choose one. 
The picker displays each directory's name but returns its full path, which we save in `dir`.
If you cancel the picker, `|| exit 0` exits the script

```bash
name=$(basename "$dir" | tr '.:' '__')
```

tmux uses `.` and `:` as separators in targets (`session:window.pane`), so a project called `my.app` would break every target that uses its name. Replace both with `_`.

```bash
attach() {
  if [[ -n "${TMUX:-}" ]]; then
    exec tmux switch-client -t "=$1"
  else
    exec tmux attach-session -t "=$1"
  fi
}
```

tmux won't let you run `attach-session` from inside another tmux session, because that would nest one session inside the other.
If `$TMUX` is set, the script is already running inside tmux, so we use `switch-client` to move the current client to the session instead.

```bash
if tmux has-session -t "=$name" 2>/dev/null; then
  attach "$name"
fi
```

Check for an existing session before creating one.
The `=` prefix requires an exact match, so choosing `blog` won't attach you to `blog-old`.

```bash
tmux new-session -d -c "$dir" -s "$name" -n dev

tmux new-window -c "$dir" -t "=$name" -n editor
tmux send-keys -t "=$name:editor" "nvim" Enter

attach "$name"
```

Otherwise, create a new session with the two windows and attach to it.

In full:

```bash
#!/usr/bin/env bash

set -euo pipefail

PROJECTS="${PROJECTS:-$HOME/Projects/}"

attach() {
  if [[ -n "${TMUX:-}" ]]; then
    exec tmux switch-client -t "=$1"
  else
    exec tmux attach-session -t "=$1"
  fi
}

dir=$(fd --type d --max-depth 1 . "$PROJECTS" |
  fzf --delimiter / --with-nth -2 --preview 'ls -A {}') || exit 0

name=$(basename "$dir" | tr '.:' '__')

if tmux has-session -t "=$name" 2>/dev/null; then
  attach "$name"
fi

tmux new-session -d -c "$dir" -s "$name" -n dev

tmux new-window -c "$dir" -t "=$name" -n editor
tmux send-keys -t "=$name:editor" "nvim" Enter

attach "$name"
```

You can of course set more options for `fzf`, or configure more search directories. That is left as an exercise for the reader.

<summary><h3>tmux Target Reference</h3></summary>

The `-t` flag is the option to set the "target" of many commands in tmux.
Depending on the command, the target can be a client, session, window, or pane.
Each has its own syntax.
This is how `man tmux` (tmux 3.6, COMMANDS section) describes it:

> Most commands accept the optional `-t` (and sometimes `-s`) argument with one of _target-client_, _target-session_, _target-window_, or _target-pane_. These specify the client, session, window or pane which a command should affect.
>
> _target-client_ should be the name of the client, typically the pty(4) file to which the client is connected, for example either of `/dev/ttyp1` or `ttyp1` for the client attached to `/dev/ttyp1`. If no client is specified, tmux attempts to work out the client currently in use; if that fails, an error is reported. Clients may be listed with the `list-clients` command.
>
> _target-session_ is tried as, in order:
>
> 1. A session ID prefixed with a `$`.
> 2. An exact name of a session (as listed by the `list-sessions` command).
> 3. The start of a session name, for example `mysess` would match a session named `mysession`.
> 4. A glob(7) pattern which is matched against the session name.
>
> If the session name is prefixed with an `=`, only an exact match is accepted (so `=mysess` will only match exactly `mysess`, not `mysession`).
>
> If a single session is found, it is used as the target session; multiple matches produce an error. If a session is omitted, the current session is used if available; if no current session is available, the most recently used is chosen.
>
> _target-window_ (or _src-window_ or _dst-window_) specifies a window in the form _session:window_. _session_ follows the same rules as for _target-session_, and _window_ is looked for in order as:
>
> 1. A special token, listed below.
> 2. A window index, for example `mysession:1` is window 1 in session `mysession`.
> 3. A window ID, such as `@1`.
> 4. An exact window name, such as `mysession:mywindow`.
> 5. The start of a window name, such as `mysession:mywin`.
> 6. As a glob(7) pattern matched against the window name.
>
> Like sessions, a `=` prefix will do an exact match only. An empty window name specifies the next unused index if appropriate (for example the `new-window` and `link-window` commands) otherwise the current window in _session_ is chosen.
>
> The following special tokens are available to indicate particular windows. Each has a single-character alternative form.
>
> | Token        |     | Meaning                              |
> | ------------ | --- | ------------------------------------ |
> | `{start}`    | `^` | The lowest-numbered window           |
> | `{end}`      | `$` | The highest-numbered window          |
> | `{last}`     | `!` | The last (previously current) window |
> | `{next}`     | `+` | The next window by number            |
> | `{previous}` | `-` | The previous window by number        |
>
> _target-pane_ (or _src-pane_ or _dst-pane_) may be a pane ID or takes a similar form to _target-window_ but with the optional addition of a period followed by a pane index or pane ID, for example: `mysession:mywindow.1`. If the pane index is omitted, the currently active pane in the specified window is used. The following special tokens are available for the pane index:
>
> | Token            |     | Meaning                                  |
> | ---------------- | --- | ---------------------------------------- |
> | `{last}`         | `!` | The last (previously active) pane        |
> | `{next}`         | `+` | The next pane by number                  |
> | `{previous}`     | `-` | The previous pane by number              |
> | `{top}`          |     | The top pane                             |
> | `{bottom}`       |     | The bottom pane                          |
> | `{left}`         |     | The leftmost pane                        |
> | `{right}`        |     | The rightmost pane                       |
> | `{top-left}`     |     | The top-left pane                        |
> | `{top-right}`    |     | The top-right pane                       |
> | `{bottom-left}`  |     | The bottom-left pane                     |
> | `{bottom-right}` |     | The bottom-right pane                    |
> | `{up-of}`        |     | The pane above the active pane           |
> | `{down-of}`      |     | The pane below the active pane           |
> | `{left-of}`      |     | The pane to the left of the active pane  |
> | `{right-of}`     |     | The pane to the right of the active pane |
>
> The tokens `+` and `-` may be followed by an offset, for example: `select-window -t:+2`.
>
> In addition, _target-session_, _target-window_ or _target-pane_ may consist entirely of the token `{mouse}` (alternative form `=`) to specify the session, window or pane where the most recent mouse event occurred (see the "MOUSE SUPPORT" section) or `{marked}` (alternative form `~`) to specify the marked pane (see `select-pane -m`).
>
> Sessions, window and panes are each numbered with a unique ID; session IDs are prefixed with a `$`, windows with a `@`, and panes with a `%`. These are unique and are unchanged for the life of the session, window or pane in the tmux server. The pane ID is passed to the child process of the pane in the `TMUX_PANE` environment variable. IDs may be displayed using the `session_id`, `window_id`, or `pane_id` formats (see the "FORMATS" section) and the `display-message`, `list-sessions`, `list-windows` or `list-panes` commands.

Here are some examples assuming a session named `dev` with windows `server` and `editor`:

| target               | means                                              |
| -------------------- | -------------------------------------------------- |
| `dev`                | the `dev` session                                  |
| `=dev`               | only a session named exactly `dev` (not `dev-old`) |
| `dev:editor`         | the active pane of the `editor` window             |
| `dev:1`              | the window at index 1                              |
| `dev:{end}`          | the highest-numbered window                        |
| `dev:editor.1`       | pane index 1 of the `editor` window                |
| `dev:editor.{right}` | the rightmost pane of the `editor` window          |
| `%3`                 | the pane with ID 3, wherever it is                 |
